# MVP 범위 — BucketLog

> Phase 0에서 만들 것과 만들지 않을 것.
> 버전 0.2 · 2026-08-17

---

## 0. 판단 기준

기능을 넣을지 말지는 항상 이 질문으로 결정합니다.

> **이 기능이 "적기"와 "완료하기" 사이의 공백을 메우는가?**

메우지 않으면 MVP에서 뺍니다. 예외 없습니다.

우선순위 표기: **P0 = MVP 필수** · P1 = MVP에 넣으면 좋음 · P2 = Phase 1 이후

## 1. 핵심 개념

### 1.1 목표 유형

| 유형 | 설명 | 예시 |
|---|---|---|
| **한 번 하기** `ONE_TIME` | 한 번 하면 끝 | 번지점프 하기, 오로라 보기 |
| **반복하기** `REPEATABLE` | 목표 횟수를 채우면 완료 | 책 12권 읽기, 새로운 카페 20곳 |

반복형은 `targetCount`를 갖고, 기록마다 카운트가 오릅니다. 목표치 도달 시 **자동 완료가 아니라 완료 제안**을 띄웁니다 — 완료를 누르는 순간이 이 앱의 감정적 정점이라 유저가 직접 눌러야 합니다.

> ⚠️ 반복형에 요일 반복·매일 체크·연속일 개념을 넣지 마세요. 목표치를 향해 **쌓이는** 것이지 매일 **하는** 것이 아닙니다.

### 1.2 상태

| 상태 | 설명 |
|---|---|
| **진행 중** `IN_PROGRESS` | 기본 |
| **완료** `COMPLETED` | 완료 인증 + 회고 |
| **접어둠** `ARCHIVED` | 안 하기로 한 것. 이유 기록 가능 |

**"접어둠"이 숨은 차별점입니다.** 다른 앱은 못 지킨 항목이 목록에 계속 남아 죄책감을 만들고, 그래서 유저가 앱을 지웁니다. 여기서는 실패가 아니라 **정리**로 다룹니다. 홈에서 즉시 사라지고, 언제든 되돌릴 수 있습니다.

### 1.3 기록의 3단계

기록의 마찰을 3단계로 나눈 것이 이 MVP의 핵심 설계입니다.

```
① 퀵 체크인   한 줄 (5초)      "아직 숙소 못 정함"
② 진행 기록   사진 + 메모       "항공권 예약 완료!" 📷
③ 완료 인증   사진 + 회고       ✅ "드디어 왔다" 📷📷
```

세 가지 모두 같은 `Entry` 테이블에 저장되고, 입력 UI만 다릅니다. **마찰이 다른 세 개의 문을 두는 것**이 목적입니다. 사진을 꺼내기 귀찮은 날에도 한 줄은 남길 수 있어야 합니다.

### 2.2 기록

| ID | 기능 | 상세 | 우선 |
|---|---|---|---|
| E-01 | **퀵 체크인** | 한 줄 메모만. 홈 카드 / 상세 상단에서 인라인 입력 | P0 |
| E-02 | 진행 기록 | 메모 + 사진(0~5장) + 날짜 | P0 |
| E-03 | 사진 촬영 / 앨범 선택 | | P0 |
| E-04 | 날짜 수정 | 과거 날짜로 소급 기록 가능 | P0 |
| E-05 | 기록 수정 / 삭제 | | P0 |
| E-06 | 반복형 카운트 | 기록 시 +1 (기본), 수동 조정 가능 | P0 |
| E-07 | 완료 인증 | 사진 + 회고 + 완료일 | P0 |
| E-08 | **회고 프롬프트** | 빈칸 대신 질문 제시 (§2.6) | P0 |
| E-09 | 대표 사진 지정 | 미지정 시 최신 사진 자동 | P1 |

**E-01 퀵 체크인 설계 원칙**

```
탭 → 입력 → 저장.  화면 전환 없음. 3초.
```

홈의 목표 카드에 인라인 입력창을 두거나, 상세 화면 상단에 "지금 어때요?" 한 줄 필드를 둡니다. **사진 첨부 버튼은 두되 선택 사항**으로, 누르면 진행 기록(E-02)으로 승격됩니다.

퀵 체크인은 카운트를 올리지 않습니다(`countDelta = 0`). 반복형에서 "카페 갔다"가 아니라 "가고 싶다"를 적을 수도 있기 때문입니다. 카운트를 올리려면 사용자가 명시적으로 토글합니다.

**E-04가 생각보다 중요합니다.** 사람들은 일을 하고 며칠 뒤에 앱을 엽니다. 오늘 날짜로만 기록되면 타임라인이 어긋나고, 그게 쌓이면 앱을 신뢰하지 않게 됩니다.

**H-07 "작년 오늘"을 권합니다.** 구글 포토·페이스북이 쓰는 회상 장치로, 구현은 쿼리 하나인데 감정 임팩트가 큽니다. 유저가 아무것도 하지 않아도 앱이 스스로 가치를 만드는 유일한 기능이라 리텐션 기여가 큽니다. 기록이 1년 이상 쌓이기 전엔 안 보이므로, **"한 달 전 오늘"까지 범위를 넓히는 것**을 고려하세요.

### 2.5 보관함 / 회고

| ID | 기능 | 상세 | 우선 |
|---|---|---|---|
| A-01 | 완료한 것들 | 사진 중심 그리드 | P0 |

### 2.6 회고 프롬프트 (E-08)

완료 화면에서 빈 텍스트 필드를 주면 대부분 아무것도 안 씁니다. 대신 **질문을 하나 띄웁니다.**

```
가장 기억에 남는 순간은?
생각과 달랐던 점이 있나요?
다시 한다면 뭘 바꿀까요?
누구랑 함께했나요?
이걸 하기 전의 나에게 한마디 한다면?
```

목표 카테고리에 따라 질문 풀을 다르게 하고, 랜덤으로 하나를 보여주되 **다른 질문 보기**로 넘길 수 있게 합니다. 건너뛰기도 항상 허용합니다.

구현 비용이 거의 없는데 회고 작성률을 크게 올리는 기능입니다. **접어두기 화면에도 같은 방식을 적용하세요** ("왜 마음이 바뀌었나요?").

### 2.7 온보딩

| ID | 기능 | 상세 | 우선 |
|---|---|---|---|
| O-01 | 프리셋 목표 | 카테고리별 예시 20~30개, 탭하면 추가 | P0 |
| O-02 | 첫 목표 등록 유도 | 온보딩 마지막 단계 | P0 |
| O-03 | 알림 권한 요청 | **첫 실행이 아니라 첫 목표 등록 직후** | P0 |

**O-01은 빼면 안 됩니다.** 빈 화면에 "목표를 추가하세요"만 있으면 대부분 여기서 이탈합니다. "뭘 적어야 할지 모르겠다"가 첫 관문입니다.

```
여행  혼자 여행 가보기 · 국내 섬 3곳 가보기 · 야간열차 타보기
취미  필름카메라로 한 롤 찍기 · 도자기 클래스 · 악기 하나 배우기
관계  부모님과 사진관에서 사진 찍기 · 오래된 친구에게 편지 쓰기
도전  5km 달리기 · 새벽 등산 · 번지점프
배움  책 12권 읽기 · 자격증 하나 따기
건강  건강검진 받기 · 아침형 인간 일주일 살기
```

**O-03의 타이밍이 중요합니다.** 첫 실행에서 알림 권한을 물으면 대부분 거절합니다. 목표를 하나 등록한 직후, "○○ 잊지 않게 가끔 알려드릴까요?" 맥락에서 물으면 승낙률이 크게 올라갑니다.

### 2.8 알림

> 전체 규칙은 `docs/NOTIFICATIONS.md`. **알림 예산(주 1회 상한)을 반드시 지키세요.**

| ID | 기능 | 상세 | 우선 |
|---|---|---|---|
| N-01 | 월간 회고 | 매월 말 "이번 달 어떤 걸 했나요?" | P0 |
| N-02 | **스마트 넛지** | 정체된 목표 **하나**를 콕 집어 "○○, 요즘 어때요?" | P0 |
| N-03 | 목표별 리마인더 | 유저가 직접 켠 목표만. **최소 주 1회 단위** | P1 |
| N-04 | 마감 임박 | 마감일 7일 전 (G-09 설정 시) | P1 |
| N-05 | 연말 회고 | 12월 "올해를 돌아볼 시간" + 이월 플로우 진입 | P1 |
| N-06 | 알림 설정 | 종류별 on/off, 시각 지정 | P0 |

**N-02 스마트 넛지가 이번에 추가된 것 중 가장 가치가 큽니다.**

일반적인 "앱을 열어보세요" 알림은 무시당합니다. 하지만 **목표 이름을 직접 부르면** 완전히 다릅니다.

```
❌  "BucketLog를 확인해보세요"
✅  "제주도 한 달 살기 — 마지막 기록 후 32일이 지났어요. 요즘 어때요?"
```

알림을 탭하면 해당 목표의 **퀵 체크인 필드로 바로 진입**합니다. 한 줄 쓰고 끝나는 경험이라 마찰이 거의 없습니다.

선정 로직: 마지막 기록으로부터 30일 이상 지난 진행 중 목표 중, **가장 오래 방치된 것 하나**. 여러 개가 정체되어도 **한 번에 하나만** 보냅니다.

**N-03 목표별 리마인더에는 강한 제약이 필요합니다.** 매일 반복을 허용하면 이 앱은 즉시 할 일 앱이 됩니다. 최소 주기는 **주 1회**이고, 기본값은 꺼짐이며, 유저가 목표별로 명시적으로 켜야 합니다.

## 3. MVP에서 명시적으로 제외

| 항목 | 이유 | 언제 |
|---|---|---|
| 로그인 / 클라우드 동기화 | 백엔드 없이 출시. 유료 훅으로 활용 | Phase 1 |
| 위젯 | Glance / WidgetKit 각각 네이티브 — 개발량 큼 | Phase 1 |
| 소셜 / 친구 / 공개 목표 | 운영 부담 급증, 유저 없으면 텅 빈 화면 | Phase 2+ |
| 결제 / 구독 | 리텐션 검증 전 수익화는 무의미 | Phase 1 |
| 연간 회고 리포트 | 완성도가 곧 가치 — 12월 목표 | Phase 1 |
| 하위 단계 체크리스트 | 진행 기록과 역할 중복, 할 일 앱처럼 보임 | 검토만 |
| 커스텀 카테고리 | 관리 UI 필요, 가치 대비 비쌈 | Phase 2 |
| 위치 태그 | 권한 이슈, 여행 목표에만 유효 | Phase 2 |
| 음성 메모 | 녹음·재생 UI 필요, 마찰 절감 대비 비쌈 | 안 함 |
| AI 목표 추천 | 비용 발생 + 핵심 가치와 무관 | 안 함 |
| **스트릭 / 연속일** | **습관 앱으로 변질됨** | **안 함** |

## 4. 개발 순서

각 주차가 끝날 때마다 **실제로 돌려보고** 다음으로 넘어가세요.

> **순서 변경 이력 (v0.2):** 원래는 "사진 파이프라인 PoC"를 0주차, 다른 코드보다 먼저 두었습니다.
> 하지만 퀵 체크인은 사진 없이 텍스트만으로도 성립하는 기록이라(§2.2 E-01), 사진 없이도
> 목표 생성→체크인→완료까지 전체 흐름을 먼저 검증할 수 있습니다. 그래서 **텍스트 기준 CRUD를
> 먼저 돌려보고, 본격적으로 화면(특히 타임라인)을 다듬기 전에 사진 파이프라인을 검증**하는
> 순서로 바꿨습니다. 사진 파이프라인이 여전히 이 앱에서 가장 리스키한 expect/actual 경계라는
> 판단은 그대로입니다 — "제일 먼저"가 아니라 "타임라인 UI 전에 반드시"로 위치만 옮긴 것입니다.

```
✅ 0주차  KMP 스캐폴딩 · com.bucketlog 패키지 정리 ·
          Room/Koin/Coil3/kotlinx-datetime/serialization 의존성 연결 ·
          domain/model 3종 (Goal/Entry/Photo) — 완료

✅ 1주차  Room DB 스키마 (DAO·엔티티·매퍼) · domain/repository·usecase (텍스트 기준) ·
          목표 CRUD 화면 · 퀵 체크인(텍스트만) 화면 — 완료
          └─ 목표 생성 → 체크인 → 완료 → 되돌리기가 사진 없이 막힘없이 도는 상태까지 확인함.
             Android 에뮬레이터 실기기 검증 완료. Room + Compose Multiplatform이 정상 동작.
             iOS 시뮬레이터 타겟은 컴파일까지만 확인(실행 검증은 미실시).

2주차  사진 파이프라인 PoC (촬영 → 압축 → 로컬 저장 → 렌더링) ·
       expect/actual 경계 확정 (ARCHITECTURE.md §3) ·
       1주차 텍스트 플로우에 사진 첨부 연결
       └─ 여기를 건너뛰고 타임라인부터 만들면, 나중에 사진이 붙을 때
          레이아웃을 다시 손봐야 합니다. 타임라인 UI 착수 전 반드시 완료.

3주차  목표 상세 타임라인 UI (사진 포함) · 완료 / 접어두기 플로우
       ← 제품이 처음 "제품처럼" 보이는 시점

4주차  홈 완성 · 보관함 · 온보딩 프리셋

5주차  알림 3종 (월간 회고 · 스마트 넛지 · 설정) · 백업/복원

6주차  완료 카드 공유 · 다크모드 마감 · 버그 · 스토어 제출
```

**2주차(사진 파이프라인)를 건너뛰고 3주차로 넘어가지 마세요.** 사진이 이 앱 콘텐츠의 핵심이라, 여기가 검증되지 않은 채 타임라인 UI를 만들면 나중에 다시 손대야 합니다.

## 5. MVP 완료 기준

```
□ 목표 생성 → 체크인 2회 → 진행 기록 1회 → 완료까지 막힘 없음
□ 퀵 체크인이 탭부터 저장까지 3초 이내
□ 사진 5장 포함 기록의 저장·로딩 1초 이내
□ 목표 50개 · 기록 300개 상태에서 홈 스크롤 60fps
□ 백업 → 앱 재설치 → 복원이 사진까지 정상 동작
□ 알림 3종이 예산 규칙(주 1회)을 위반하지 않음
□ 본인이 2주간 실제 목표로 사용해도 불편하지 않음
□ Android / iOS 스토어 출시
```

## 6. 출시 후 볼 지표

| 지표 | 목표 | 의미 |
|---|---|---|
| 온보딩 완료율 (첫 목표 등록) | 70% | 프리셋이 작동하는가 |
| **목표당 평균 기록 수** | **2.5+** | **최우선.** 1에 가까우면 컨셉 실패 |
| 퀵 체크인 / 전체 기록 비율 | 50%+ | 마찰 3단계 설계가 먹히는가 |
| 스마트 넛지 → 기록 전환율 | 20% | 넛지가 진짜 효과 있는가 |
| D30 리텐션 | 20% | |
| 완료 카드 공유율 | 완료 건의 10% | 유입 경로 검증 |

**"목표당 평균 기록 수"가 이 제품의 생명선입니다.** 이 숫자가 1에 가까우면 사람들이 여전히 체크리스트로 쓰고 있다는 뜻이고, 그러면 차별점이 없습니다. 그때는 기능을 늘리지 말고 **기록의 마찰을 줄이는 데** 집중하세요.
