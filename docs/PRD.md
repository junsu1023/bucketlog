# PRD — BucketLog (버킷로그)

> 제품 요구사항 정의서
> 버전 0.1 · 2026-08-17

---

## 1. 문제 정의

사람들은 "올해는 이것만은 해보자"를 마음에 품고 삽니다. 혼자 여행 가보기, 부모님과 사진관에서 사진 찍기, 책 열두 권 읽기 같은 것들이요.

그런데 이걸 담을 도구가 마땅치 않습니다.

- **할 일 앱**은 이 목표들을 처리해야 할 업무로 만듭니다. 체크박스는 "번지점프"를 "장보기"와 같은 무게로 다룹니다
- **습관 앱**은 매일 하는 것만 다룹니다. 1년에 한 번 하는 일에는 맞지 않습니다
- **기존 버킷리스트 앱**은 목록만 있습니다. 적고 나면 열 이유가 없고, 못 지킨 항목이 쌓이면 죄책감이 되어 앱을 지웁니다

**빠져 있는 건 "과정"입니다.**

제주도 한 달 살기를 완료하기까지 숙소를 알아보고, 항공권을 예약하고, 짐을 싸는 몇 달이 있습니다. 그 과정이 사실 목표 자체보다 기억에 남는데, 어떤 앱도 그걸 담지 않습니다.

---

## 2. 제품 정의

> **작은 목표를 적고, 해나가는 과정을 사진과 메모로 기록하고, 나중에 돌아보는 앱.**

할 일 목록이 아니라 **추억 아카이브**입니다.

### 세 문장 요약

1. 올해 하고 싶은 것들을 적는다
2. 해나가는 동안 사진과 한 줄을 남긴다
3. 연말에 그게 한 권의 기록이 되어 돌아온다

---

## 3. 타겟 사용자

### Primary
- **20대 중반 ~ 30대 초반**
- 새해에 목표를 세우지만 3월이면 잊는 사람
- 사진으로 일상을 남기는 습관이 있음
- 할 일 앱은 써봤지만 "관리당하는" 느낌이 싫었던 사람

### Secondary
- 10대 후반 ~ 20대 초반 — 대학 시절 버킷리스트
- 30대 후반 이상 — 가족 단위 목표, 연간 회고 니즈

### 페르소나

> **이서연(27, 직장인)** — 매년 1월에 노션에 버킷리스트를 만든다. 2월까지는 본다. 작년 리스트를 12월에 열어봤더니 20개 중 3개를 했는데, 사실 더 했던 것 같은데 기록이 없어서 기억이 안 났다. 못 한 17개만 눈에 들어와서 기분이 나빴다.

이 페르소나의 두 가지 좌절이 제품의 두 축입니다.
- "더 했는데 기억이 안 난다" → **진행 기록**
- "못 한 것만 눈에 들어온다" → **접어두기**

## 4. 핵심 가치

| 순간 | 가치 |
|---|---|
| 적을 때 | 부담 없이. 프리셋에서 골라도 됨 |
| 하는 중 | 한 줄만 남겨도 기록이 됨 |
| 완료할 때 | 사진과 회고가 하나로 묶임 |
| 안 하기로 할 때 | 죄책감 없이 정리됨 |
| 돌아볼 때 | 잊고 있던 것들이 돌아옴 |

---

## 5. 이 앱이 반드시 이겨야 할 것

> **목표를 적고 나면 앱을 열 이유가 없다.**

이 카테고리 앱이 죽는 유일한 이유입니다. 완료는 1년에 몇 번뿐이니 그 사이 공백이 몇 달씩 생기고, 그 공백에 유저를 잃습니다.

**MVP의 모든 설계는 이 공백을 메우는 데 집중합니다.**

| 장치 | 어떻게 |
|---|---|
| 진행 기록 | 완료 전에도 남길 게 있다 |
| 퀵 체크인 | 한 줄이면 된다 — 마찰 최소 |
| 접어두기 | 못 지킨 목록이 쌓이지 않는다 |
| 스마트 넛지 | 앱이 목표 이름을 부르며 물어본다 |
| 월간 회고 | 앱이 먼저 말을 건다 |
| 작년 오늘 | 과거 기록이 스스로 돌아온다 |

상세 명세는 `docs/MVP-SCOPE.md`.

## 6. 경쟁 환경

| 유형 | 예시 | 이 앱과의 차이 |
|---|---|---|
| 할 일 앱 | Todoist, TickTick | 업무 처리 도구. 감정·기억이 없음 |
| 습관 앱 | Habitica, Streaks | 매일 반복 전제. 연 1회 목표에 부적합 |
| 버킷리스트 앱 | 다수의 소규모 앱 | 목록 중심, 과정 기록이 없음 |
| 일기 앱 | Day One | 기록은 있지만 목표 구조가 없음 |

**포지셔닝: 버킷리스트 앱과 일기 앱 사이.**

목표라는 뼈대가 있고, 그 위에 기록이 붙습니다. 목표 없는 일기는 흩어지고, 기록 없는 목표는 죄책감이 됩니다.

### 차별화의 실체

기능 목록으로는 차별화되지 않습니다. 실제 차별점은 셋입니다.

1. **타임라인 UI의 완성도** — 목표 상세 화면이 예쁘지 않으면 이 앱은 존재 이유가 없습니다
2. **톤** — "포기" 대신 "접어두기". `docs/DESIGN.md`가 이걸 다룹니다
3. **알림의 절제** — 주 1회 상한. 대부분의 앱이 여기서 실패합니다

## 7. 기능 개요

전체 명세는 `docs/MVP-SCOPE.md`. 여기서는 구조만 봅니다.

```
목표 (Goal)
├─ 유형: 한 번 하기 / 반복하기
├─ 상태: 진행 중 / 완료 / 접어둠
├─ 버킷: 2026 / 언젠가
└─ 기록 (Entry)
     ├─ 퀵 체크인   한 줄 (5초)
     ├─ 진행 기록   사진 + 메모
     └─ 완료 인증   사진 + 회고
```

## 8. 성공 지표

| 단계 | 지표 | 목표 |
|---|---|---|
| Phase 0 | 온보딩 완료율 | 70% |
| Phase 0 | **목표당 평균 기록 수** | **2.5+** |
| Phase 0 | 퀵 체크인 비율 | 전체 기록의 50%+ |
| Phase 0 | D30 리텐션 | 20% |
| Phase 1 | 넛지 → 기록 전환율 | 20% |
| Phase 1 | 완료 카드 공유율 | 완료 건의 10% |
| Phase 1 | 유료 전환율 | 2% |

**"목표당 평균 기록 수"가 제품의 생명선입니다.** 이 값이 1에 가까우면 사람들이 여전히 이 앱을 체크리스트로 쓰고 있다는 뜻이고, 그러면 차별점이 존재하지 않습니다.

---

## 9. 범위 밖 (Non-goals)

명시적으로 하지 않는 것들입니다.

- ❌ **습관 트래킹** — 매일 체크, 스트릭, 연속일. 이걸 넣는 순간 다른 제품이 됨
- ❌ **할 일 관리** — 하위 작업, 우선순위, 마감 압박
- ❌ **소셜 네트워크** — 팔로우, 피드, 좋아요. 이건 개인 아카이브
- ❌ **성과 평가** — 달성률 순위, 등급, 점수
- ❌ **AI 추천** — 비용 대비 가치 없음
- ❌ **커머스 / 제휴** — 목표를 소비로 유도하지 않음
