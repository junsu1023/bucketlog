## 0. 브랜드 컨셉 & 무드

**목표를 기록하고, 그 과정을 추억으로 남긴다.**

목표를 적는 순간에는 미래를 향한 작은 계획이지만, 시간이 지나면 사진과 기록이 더해진 하나의
기억이 된다. 이 이중적 성격(목표 ↔ 추억)이 디자인이 표현해야 할 핵심 감정이다. UI는 사용자를
독려하거나 평가하지 않고, **기록을 담담하게 보관하고 다시 꺼내보게 하는 사진첩**처럼 느껴져야
한다.

### 무드 키워드

`따뜻함` · `담담함` · `기록` · `아카이브` · `여백` · `시간의 흐름` · `오래된 사진첩`

### 비주얼 방향

- 사진이 UI보다 먼저 보인다 — 강한 그림자·테두리 대신 여백으로 계층을 만든다.
- 검은색은 차갑기보다 **따뜻한 블랙**(순수 `#000000`이 아니라 미세하게 따뜻한 톤).
- 강조색은 Amber/Gold, 완료색은 Olive. 미완료·접어둠에는 부정적 시각 언어(빨강, 경고 아이콘)를
  쓰지 않는다.
- Material 3을 기반으로 하되, 기본 Material 스타일보다 **에디토리얼하고 사진첩에 가까운 느낌**으로
  커스터마이징한다(테두리 제거, 모서리를 더 둥글게, 세리프 타이틀).

## 1. 톤의 원칙

이 앱은 사람의 "못 지킨 것"을 다룹니다. 대부분의 목표는 완료되지 않고, 그건 정상입니다.

> ### 이 앱은 코치가 아니라 일기장이다.

성과를 평가하지 않고, 재촉하지 않고, 기록을 도울 뿐입니다.

| | 하지 않음 | 함 |
|---|---|---|
| 역할 | 코치 · 트레이너 | 일기장 · 기록 도구 |
| 초점 | 달성률 · 성과 | 경험 · 기억 |
| 어조 | 독려 · 채찍질 | 담담한 안내 |
| 미완료 | 실패 | 아직 하지 않은 것 |

**개발자/디자이너가 항상 기억할 5가지**

1. 우리는 사용자를 관리하지 않는다. 기록을 보관한다.
2. 완료는 축하하지만, 미완료를 실패로 만들지 않는다.
3. 사진이 주인공이고 UI는 사진을 담는 액자다.
4. 색과 애니메이션은 조용하게 사용한다.
5. 시간이 지나 다시 열었을 때 더 가치 있어지는 UI를 만든다.

### 2.1 색상 규칙

**Accent 위 텍스트는 항상 짙은 색(`#1E1E1B`)을 쓴다 — 흰색을 쓰지 않는다.**
라이트·다크 Accent 둘 다 밝은 골드 톤이라, 흰 텍스트/아이콘을 올리면 대비가 **2.3:1**까지
떨어져 §8 접근성 기준(최소 3:1)에 못 미친다. 반대로 짙은 텍스트는 9:1 이상으로 여유 있게
통과한다. FAB 아이콘, 선택된 칩의 텍스트 모두 이 규칙을 따른다
(`MaterialTheme.colorScheme.onPrimary` / `onSecondaryContainer`가 이미 이 색으로 연결돼 있다).

**Accent는 중요한 액션에만 사용한다.** FAB, 선택된 칩/탭, 타임라인의 진행·완료 노드 등. 일반
텍스트를 강조하기 위해 남발하지 않는다.

**Completed는 `Green`보다는 `Olive`에 가깝게 유지한다.** 성공을 알리는 초록색이 아니라 "기록이
하나 완성되었다"는 느낌이어야 한다.

**Paused(접어둠)는 회색 계열만 사용한다. 빨간색 금지.** 완료와 반대되는 의미(실패)로 표현하지
않는다.

**Error는 실제 오류에만 사용한다.** 목표 상태(접어둠 등) 표현에는 쓰지 않는다.

## 3. 타이포그래피

### 폰트 방향과 실제 적용

| 용도 | 폰트 | 적용 방식 |
|---|---|---|
| 목표 제목 / Display | Playfair Display (세리프) | 임베드(가변 폰트), `headlineSmall`/`titleLarge`/`titleMedium` |
| 날짜 / 수치 | JetBrains Mono | 임베드(가변 폰트), `MonoLabel()`로 합성 |
| 본문 / UI / 한글 전반 | 시스템 기본 폰트 | 별도 임베드 없음 |

**Noto Sans KR을 따로 임베드하지 않는다.** 완전한 CJK 글리프 세트를 굵기별로 여러 개 담으면 앱
용량이 수십 MB 늘어난다. Android는 이미 Noto Sans 계열이 시스템 기본 폰트라 사실상 동일하고,
iOS(Apple SD Gothic Neo)도 톤이 크게 다르지 않다.

**Playfair Display/JetBrains Mono는 한글 글리프가 없다.** 목표 제목이 한글이면(대부분의 실제
사용 케이스) 그 글자들은 자동으로 시스템 기본 폰트로 폴백되고, 지정한 굵기(SemiBold 등)만
반영된다. 세리프 처리는 실질적으로 **영문·숫자가 섞인 제목**에서 가장 잘 드러난다 — 완전한
한글 명조체를 원한다면 Noto Serif KR 같은 한글 세리프 폰트를 별도로 임베드해야 하며, 이 역시
CJK 폰트라 용량 트레이드오프가 동일하게 따른다(필요해지면 별도로 논의).

두 폰트 다 정적 굵기 파일이 아니라 **가변 폰트(variable font)** 하나에 여러 굵기의 `Font()`
엔트리를 등록해 인스턴싱한다. 실제 코드는
`shared/src/commonMain/kotlin/com/bucketlog/presentation/theme/Type.kt`.

### Type Scale

| 용도 | 크기 | Weight | Line Height | 비고 |
|---|---:|---|---:|---|
| Display / 섹션 헤더 | `28sp` | SemiBold | `140%` | `headlineSmall` — 온보딩 타이틀 등 |
| Title 1 (화면 타이틀) | `22sp` | SemiBold | `140%` | `titleLarge` — 목표 상세, 다이얼로그 제목 |
| Title 2 (카드 제목) | `18sp` | Medium | `140%` | `titleMedium` — 홈 목표 카드 제목 |
| Body | `16sp` | Regular | `160%` | `bodyLarge` — 본문/메모 |
| Body Small(보조 텍스트) | `14sp` | Regular | `150%` | `bodyMedium` — 마지막 기록 시점 등 |
| Caption | `12sp` | Regular | `140%` | `bodySmall` — 플레이스홀더 등 |
| 날짜 / 수치 | 기반 스타일 그대로 | Regular/Medium | 기반 그대로 | `MonoLabel()`을 `.merge()` |

### Compose 적용 원칙

고정 sp를 절대 기준으로 쓰지 않는다. `MaterialTheme.typography.*`를 통해서만 텍스트 스타일을
가져오고, 시스템 글꼴 크기 설정이 커지면 레이아웃도 자연스럽게 늘어나야 한다.

```kotlin
MaterialTheme.typography.titleLarge   // Title 1
MaterialTheme.typography.titleMedium  // Title 2
MaterialTheme.typography.bodyLarge    // Body
MaterialTheme.typography.bodyMedium   // Body Small
MaterialTheme.typography.bodySmall.merge(MonoLabel())  // 날짜/수치
```

## 5. 컴포넌트 스타일

### 5.1 목표 카드 (홈)

앱에서 가장 중요한 컴포넌트. `HomeScreen.kt`의 `GoalCard`.

- 대표 사진(16:9)이 카드의 첫 번째 시각 요소. 사진 위에 강한 그라디언트를 쓰지 않는다.
- 테두리 없음(`Card`, `OutlinedCard` 아님), 모서리 16dp.
- 카테고리는 칩으로 — Surface Container 배경, 테두리 없음, 캡슐형.
- 목표 제목이 카드에서 가장 큰 텍스트(Title 2, 세리프).
- 마지막 기록 날짜는 보조 텍스트 + 모노스페이스.
- 퀵 체크인은 카드 안에서 바로 입력 가능해야 한다.
- **Progress Bar 사용 금지** — 진행률 시각화가 "관리당하는" 느낌을 준다.

### 5.2 타임라인 (목표 상세)

**이 앱의 핵심 UI.** 단순한 진행 상태 표시가 아니라 시간이 쌓이는 모습을 보여주는 기록 UI다.
`GoalDetailScreen.kt`의 `TimelineNode`/`TimelineRail`.

| 기록 종류 | 노드 형태 | 크기 |
|---|---|---:|
| 체크인 | 채워진 점 | 4dp |
| 진행 기록 | 채워진 원 | 8dp |
| 완료 | 채워진 원 + 체크 표시 | 16dp |

- 세로선: 두께 1dp, 색상 = 보조 텍스트色의 35% 불투명도. 화면을 강하게 가르지 않는다.
- **핵심 원칙: 노드의 크기는 성과의 크기가 아니라 기록의 중요도를 나타낸다.**

### 5.3 다이얼로그

확인/삭제 다이얼로그는 최대한 담담하게 만든다. 예(목표 접어두기):

```
제목   이 목표를 접어둘까요?
본문   보관함으로 옮겨져요. 생각이 바뀌면 언제든 다시 꺼낼 수 있어요.
액션   취소 / 접어두기
```

삭제처럼 되돌릴 수 없는 작업만 확인 버튼에 Error 색(`colorScheme.error`)을 쓴다. "정말
포기하시겠습니까?" 같은 문구는 절대 쓰지 않는다 — 자세한 문구 규칙은 §9.

### 5.4 FAB

앱의 주요 행동인 "기록하기"/"목표 만들기"를 담당.

- 원형, 56dp, 그림자·elevation 최소화.
- 배경 = Accent, 아이콘/텍스트 = On Accent(짙은 색, §2.1).

### 5.5 카테고리 칩

카테고리: 여행 · 취미 · 관계 · 도전 · 배움 · 건강 · 기타(고정 세트, `docs/DATA-MODEL.md` 참고).

- 모서리 16dp(캡슐에 가깝게), 테두리 없음.
- 기본 배경 = Surface Container(§2 표). 선택 상태만 Accent + On Accent 텍스트.
- 앱 전역에서 이 색 규칙은 `MaterialTheme`의 `secondaryContainer`/`onSecondaryContainer`를
  Accent/On Accent로 지정해 자동 적용된다 — 화면마다 칩 색을 따로 지정할 필요가 없다.

### 5.6 빈 상태

사용자를 독려하지 않는다.

```
❌  아직 아무것도 하지 않았어요! 지금부터 목표를 시작해보세요!
✅  아직 기록이 없어요. 올해의 작은 목표 하나를 적어볼까요?
```

화면별 문구는 §9.3 참고.

### 5.7 사진 그리드

보관함의 사진이 주인공.

- 2열, 간격 4dp, 모서리 8dp, 비율 1:1. 테두리·그림자 없음.
- 스크림(어두운 오버레이) 위 텍스트는 라이트/다크 테마와 무관하게 항상 흰색 고정 — 스크림 자체가
  항상 어둡게 깔리기 때문에, 테마를 따라가는 색(예: `colorScheme.surface`)을 쓰면 다크 모드에서
  어두운 배경 위에 어두운 텍스트가 겹쳐 안 보이는 문제가 생긴다(이번 리뉴얼에서 발견해 수정).

## 6. 모션 & 인터랙션

### 원칙

> **"애니메이션을 보여주기 위해 애니메이션을 사용하지 않는다."**

애니메이션은 사용자가 상태 변화를 자연스럽게 이해하는 데 도움이 될 때만 사용한다.

| 사용한다 | 시간 | 설명 |
|---|---:|---|
| 목표 완료 | 300~400ms | 타임라인 노드가 점 → 체크 표시된 원으로. 짧은 scale 애니메이션. 폭죽/confetti 없음 |
| 사진 추가 | 200~250ms | 새 사진이 그리드에 Fade + Scale In |
| 화면 이동 | 200~300ms | Fade / Shared Axis 계열 |
| 다이얼로그 | 200ms | Fade + Scale |

**사용하지 않는다**: 스트릭 증가 애니메이션 · Progress Bar 증가 애니메이션 · 미완료 경고
애니메이션 · 반복적인 confetti · 독려용 진동 · 계속 움직이는 습관 앱류 UI.

### 기존 인터랙션 원칙(유지)

| 원칙 | 의미 |
|---|---|
| 퀵 체크인은 3초 | 탭 → 입력 → 저장. 화면 전환 없음 |
| 필수 입력 없음 | 사진만, 메모만, 둘 다 모두 허용 |
| 파괴적 동작은 되돌릴 수 있게 | 삭제·완료·접어두기 모두 확인 다이얼로그 또는 되돌리기 제공 |
| 로딩 대신 자리 잡기 | 스피너보다 스켈레톤. 사진은 width/height로 미리 자리 확보 |
| 키보드가 화면을 가리지 않게 | 특히 퀵 체크인 |

---

## 7. 아이콘 시스템

- Outline 아이콘 중심, Stroke 1.5dp, Round Cap/Join, 기본 24dp.
- Filled 아이콘은 상태를 표현할 때만 제한적으로(완료 체크, 선택된 내비게이션 등). 일반 액션은
  Outline.

| 용도 | 크기 |
|---|---:|
| Navigation | 24dp |
| Button | 20~24dp |
| Inline | 18dp |
| Small metadata | 16dp |

## 8. 접근성 체크리스트

- 일반 텍스트 대비 **최소 4.5:1**, 큰 텍스트/아이콘 **최소 3:1**.
- Accent(Amber/Gold) 위 텍스트·아이콘은 반드시 짙은 색 — §2.1 참고(흰색은 2.3:1로 기준 미달).
- 완료/접어둠 상태를 색만으로 구분하지 않는다 — 완료는 색+체크 아이콘, 접어둠은 색+아이콘.
- 최소 터치 영역 48×48dp, FAB는 56×56dp.
- 시스템 폰트 크기 설정 존중(고정 sp 금지) — 특히 목표 제목/타임라인 기록/다이얼로그/설정 항목이
  잘리지 않게.
- 모든 이미지에 contentDescription — 사진은 해당 기록의 메모를 사용.
- 접근성 설정에서 애니메이션 감소가 켜져 있으면 scale 애니메이션 제거, 상태 변화는 색/아이콘/구조
  변화만으로 전달.

### 9.2 상황별 문구

**접어두기**

```
버튼         이건 안 하기로 하기
확인 제목     이 목표를 접어둘까요?
확인 본문     보관함으로 옮겨져요. 생각이 바뀌면 언제든 다시 꺼낼 수 있어요.
이유 입력     왜 마음이 바뀌었나요?  (선택)
완료 토스트   접어뒀어요. 보관함에 있어요.
```

**"정말 포기하시겠습니까?" 같은 문구를 절대 쓰지 마세요.** 접어두는 건 나쁜 일이 아니고,
오히려 목록을 정리하는 건강한 행동입니다.

**완료**

```
버튼         완료했어요
회고 안내     남기고 싶은 말이 있나요?  (건너뛸 수 있어요)
완료 토스트   기록했어요.
```

과한 축하(폭죽, "축하합니다!!!")는 피합니다. 짧은 애니메이션 하나면 충분합니다.

**빈 상태**

```
홈 (목표 없음)
  올해 하고 싶은 걸 하나 적어볼까요?
  [예시에서 고르기]  [직접 쓰기]

목표 상세 (기록 없음)
  아직 기록이 없어요.
  한 줄이라도 남겨두면 나중에 반가워요.

보관함 (완료 없음)
  완료한 것들이 여기 모여요.
```

**퀵 체크인 플레이스홀더**

```
지금 어때요?
한 줄만 남겨도 좋아요
```

**알림** — `docs/NOTIFICATIONS.md`에 종류별 문구 규칙이 있습니다. 공통 원칙:

> **숫자로 평가하지 말고, 질문으로 초대할 것.**

```
❌  "이번 달 목표를 3개 중 0개 달성했어요"
✅  "9월이 지나갔어요. 이번 달엔 어떤 걸 했나요?"
```

### 9.3 회고 프롬프트

완료 시 랜덤으로 하나 제시. **[다른 질문]** 과 **[건너뛰기]** 를 항상 함께 둡니다.

```
공통    가장 기억에 남는 순간은?
        생각과 달랐던 점이 있나요?
        누구랑 함께했나요?

여행    어떤 장면이 제일 오래 남을까요?
도전    가장 힘들었던 순간은?
배움    무엇을 새로 알게 됐나요?
관계    어떤 이야기를 나눴나요?
```
