# 알림 설계 — BucketLog

> 알림 관련 코드를 쓰기 전 **반드시** 이 문서를 읽으세요.
> 버전 0.1 · 2026-08-17

---

## 0. 왜 별도 문서인가

이 앱에서 알림은 **리텐션의 유일한 능동적 장치**입니다. 유저가 스스로 앱을 열 이유가 적기 때문입니다.

동시에 **가장 빠르게 앱을 삭제시키는 원인**이기도 합니다. "못 지킨 목표"를 상기시키는 알림은 죄책감을 주고, 죄책감은 삭제로 이어집니다.

즉 알림은 이 제품에서 가장 강력하면서 가장 위험한 기능입니다. 그래서 규칙을 따로 못 박습니다.

---

## 1. 알림 예산 (Notification Budget) ⚠️

> ### 전체 알림 합계는 **주 1회**를 넘지 않는다.

목표가 3개든 30개든 상관없습니다. 유저가 받는 알림 총량의 상한입니다.

### 구현 방식

모든 알림은 반드시 `NotificationBudget`을 통과해야 합니다. 개별 스케줄러가 직접 알림을 띄우는 코드를 만들지 마세요.

```kotlin
interface NotificationBudget {
    /** 지금 이 알림을 보내도 되는지 */
    suspend fun canSend(type: NotificationType): Boolean

    /** 발송 기록 */
    suspend fun recordSent(type: NotificationType, at: Instant)

    /** 마지막 발송 시각 */
    suspend fun lastSentAt(): Instant?
}
```

```
발송 요청
   │
   ├─ 마지막 발송 후 7일 미만?      → 취소 (재시도 없음)
   ├─ 유저가 해당 종류를 껐는가?     → 취소
   ├─ 조용한 시간(21:00~09:00)?     → 다음 허용 시각으로 연기
   └─ 통과                          → 발송 + recordSent()
```

### 우선순위

같은 주에 여러 알림이 경합하면 아래 순서로 하나만 보냅니다.

```
1. 연말 회고 (12월)       ← 연 1회, 가장 중요
2. 마감 임박              ← 시의성이 있음
3. 월간 회고              ← 정기
4. 목표별 리마인더         ← 유저가 명시적으로 켠 것
5. 스마트 넛지            ← 가장 낮음. 밀려도 다음 주에 보내면 됨
```

## 2. 알림 종류

### N-01 월간 회고

| 항목 | 값 |
|---|---|
| 시점 | 매월 말일 (또는 마지막 일요일) |
| 시각 | 유저 설정, 기본 20:00 |
| 기본값 | **켜짐** |
| 탭 시 | 보관함 → 이번 달 기록 뷰 |

**문구는 실적을 묻지 않습니다.** "몇 개 완료했나요"는 압박이고, "무엇을 했나요"는 회상입니다.

```
✅  "9월이 지나갔어요. 이번 달엔 어떤 걸 했나요?"
✅  "이번 달 기록 7개가 쌓였어요. 한번 볼까요?"
❌  "이번 달 목표를 3개 중 0개 달성했어요"
❌  "목표 달성률이 낮아요. 분발하세요!"
```

기록이 0건인 달에는 **보내지 않습니다.** 아무것도 안 한 사람에게 회고를 권하는 건 죄책감만 줍니다.

---

### N-02 스마트 넛지 ⭐

이 앱에서 가장 효과적인 알림입니다. 핵심은 **목표 이름을 직접 부르는 것**입니다.

```
❌  "BucketLog를 확인해보세요"
✅  "제주도 한 달 살기 — 마지막 기록 후 32일이 지났어요. 요즘 어때요?"
```

| 항목 | 값 |
|---|---|
| 시점 | 주 1회 (예: 일요일 저녁) |
| 조건 | 마지막 기록 후 **30일 이상** 지난 `IN_PROGRESS` 목표 존재 |
| 대상 | 그중 **가장 오래 방치된 것 하나** |
| 기본값 | **켜짐** |
| 탭 시 | 해당 목표 상세 → **퀵 체크인 필드에 포커스** |

**탭 후 경험이 이 기능의 전부입니다.** 알림을 열었더니 목록이 나오면 유저는 다시 닫습니다. 커서가 깜빡이는 한 줄 입력창이 나와야 "아직 준비 중"이라도 치고 나갑니다.

#### 선정 로직

```kotlin
fun pickNudgeTarget(goals: List<Goal>, entries: List<Entry>, now: Instant): Goal? =
    goals
        .filter { it.status == IN_PROGRESS }
        .filter { it.bucketYear != null }              // "언젠가"는 넛지 대상 아님
        .map { it to lastEntryAt(it, entries) }
        .filter { (_, last) -> now - last >= 30.days }
        .minByOrNull { (_, last) -> last }             // 가장 오래된 것
        ?.first
```

**"언젠가" 버킷은 넛지하지 않습니다.** 유저가 의도적으로 기한을 두지 않은 것이므로 재촉하면 안 됩니다.

#### 하지 말아야 할 것

- 여러 목표를 나열하지 마세요. 정체된 목표 5개를 한꺼번에 보여주면 그건 성적표입니다
- 같은 목표를 연속으로 넛지하지 마세요. 2회 연속 무응답이면 그 목표는 **4주간 넛지 제외**
- 넛지 3회 연속 무응답 시 넛지 자체를 자동으로 잠시 멈추고, 앱 내에서 다시 켤 수 있게 안내

### N-03 목표별 리마인더

유저가 특정 목표에 직접 켜는 알림입니다.

| 항목 | 값 |
|---|---|
| 기본값 | **꺼짐** (목표별로 유저가 켬) |
| 최소 주기 | **주 1회** — 매일 옵션 제공 금지 |
| 선택지 | 주 1회 / 2주 1회 / 월 1회 |
| 탭 시 | 목표 상세 → 퀵 체크인 |

> ⚠️ **매일 반복을 절대 제공하지 마세요.** 제공하는 순간 이 앱은 할 일 앱이 되고, 유저는 습관 트래커와 비교하기 시작합니다. `CLAUDE.md` 절대 규칙 7번.

여러 목표에 리마인더가 켜져 있어도 **알림 예산은 여전히 주 1회**입니다. 같은 주에 겹치면 하나만 나가고 나머지는 조용히 스킵합니다 (다음 주로 이월하지 않습니다 — 밀린 알림이 몰려 나가는 게 최악입니다).

### N-04 마감 임박

| 항목 | 값 |
|---|---|
| 조건 | `dueDate` 설정된 목표 |
| 시점 | 마감 7일 전 (1회만) |
| 기본값 | 켜짐 |

**"D-1", "오늘 마감" 같은 압박 알림은 보내지 않습니다.** 이 앱의 마감일은 계약이 아니라 참고선입니다. 7일 전 한 번이면 충분합니다.

```
✅  "'자격증 따기' 마감일이 다음 주네요. 어떻게 되어가나요?"
❌  "D-1! 오늘이 마지막 기회입니다"
```

---

### N-05 연말 회고

연 1회, 이 앱에서 가장 중요한 알림입니다.

| 항목 | 값 |
|---|---|
| 시점 | 12월 중순 1회 + 12월 31일 1회 |
| 탭 시 | 연말 회고 화면 → **이월 플로우**(G-12) |
| 기본값 | 켜짐 |

```
"2026년이 한 달 남았어요. 올해 무엇을 했는지 볼까요?"
```

연말 회고는 단순 알림이 아니라 **연간 사이클을 다음 해로 잇는 장치**입니다. 회고 → 미완료 목표 이월 → 새해 버킷 작성으로 자연스럽게 이어지게 설계하세요. 이 흐름이 끊기면 1월에 유저를 통째로 잃습니다.

## 3. 조용한 시간

```
21:00 ~ 09:00  발송 금지
```

이 시간대에 발송 조건이 충족되면 **다음 허용 시각으로 연기**합니다. 취소하지 않습니다.

기본 발송 시각은 **20:00**입니다. 하루를 돌아보는 시간대이고, 이 앱의 성격과 맞습니다.

## 4. 권한 요청 타이밍

```
❌  앱 첫 실행 시
✅  첫 목표를 등록한 직후
```

첫 실행에서 물으면 대부분 거절합니다. 목표를 하나 등록한 직후, 맥락이 있는 상태에서 물어야 승낙률이 올라갑니다.

```
"'제주도 한 달 살기' 잊지 않게 가끔 알려드릴까요?
 한 달에 한두 번이면 충분해요."
```

거절해도 앱은 완전히 동작해야 하고, **재요청은 하지 않습니다.** 설정에서 언제든 켤 수 있다는 안내만 한 번 노출합니다.

## 5. 설정 화면 (N-06)

유저가 종류별로 켜고 끌 수 있어야 합니다.

```
알림
├─ 전체 알림                    [ON]
├─ 월간 회고                    [ON]
├─ 오래된 목표 살펴보기 (넛지)    [ON]
├─ 마감 임박                    [ON]
├─ 연말 회고                    [ON]
└─ 알림 받을 시각               [20:00]
```

**"스마트 넛지"라는 개발자 용어를 UI에 노출하지 마세요.** "오래된 목표 살펴보기" 처럼 유저 언어로 표기합니다.

## 6. 기술 구현

### expect/actual

```kotlin
// commonMain
expect class NotificationScheduler {
    suspend fun schedule(notification: LocalNotification)
    suspend fun cancel(id: String)
    suspend fun cancelAll()
    suspend fun hasPermission(): Boolean
    suspend fun requestPermission(): Boolean
}

data class LocalNotification(
    val id: String,
    val type: NotificationType,
    val title: String,
    val body: String,
    val scheduledAt: Instant,
    val deepLink: String,      // bucketlog://goal/{id}?focus=checkin
)
```

| 플랫폼 | 구현 |
|---|---|
| Android | `WorkManager` + `NotificationManagerCompat` |
| iOS | `UNUserNotificationCenter` |

### 딥링크

모든 알림은 딥링크를 갖습니다. **알림을 탭했는데 홈 화면이 나오면 그 알림은 실패한 것입니다.**

```
bucketlog://goal/{goalId}?focus=checkin    스마트 넛지, 리마인더
bucketlog://archive?month=2026-09          월간 회고
bucketlog://retrospect/2026                연말 회고
```

### 스케줄링 전략

MVP는 백엔드가 없으므로 **전부 로컬 알림**입니다.

- 월간 회고 / 연말 회고: 고정 일정 → 앱 실행 시 다음 1회분만 예약
- 스마트 넛지: 주 1회 백그라운드 작업에서 조건 평가 후 예약
- 마감 임박: 목표 저장 시점에 예약, 마감일 변경 시 재예약

iOS는 예약 가능한 로컬 알림이 **64개로 제한**됩니다. 목표별 리마인더를 무제한 예약하면 한도를 넘깁니다. 항상 **가까운 미래분만 예약**하고 앱 실행 시 갱신하세요.

## 7. 체크리스트

알림 관련 PR 전에 확인하세요.

```
□ NotificationBudget을 통과하는가 (직접 발송 금지)
□ 주 1회 상한을 위반할 수 있는 경로가 없는가
□ 조용한 시간(21~09시)을 존중하는가
□ 딥링크가 정확한 화면 + 상태로 진입하는가
□ 문구가 실적/달성률을 언급하지 않는가
□ 문구가 죄책감을 유발하지 않는가 (docs/DESIGN.md 톤 가이드)
□ 유저가 이 알림을 끌 수 있는가
□ iOS 64개 제한을 넘길 수 있는 경로가 없는가
□ 권한 거절 상태에서도 앱이 정상 동작하는가
```
